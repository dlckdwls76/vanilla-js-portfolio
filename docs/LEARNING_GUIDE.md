## 2. HTML은 ‘이것이 무엇인지’를 말한다

`header`는 도입 영역, `nav`는 주요 탐색, `main`은 본문, `section`은 주제별 묶음, `footer`는 마무리 정보입니다. 저장소 카드 하나는 독립적으로 읽을 수 있어 `article`로 만듭니다.

시맨틱 태그만으로 접근성이 완성되지는 않습니다. 섹션 제목, 이미지 대체 텍스트, 폼 레이블, 키보드 조작도 함께 연결해야 합니다.

**실습:** CSS 연결을 잠깐 해제해도 순서와 의미를 이해할 수 있는지 확인하고 되돌려보세요.

## 3. Flexbox와 Grid

Flexbox는 한 방향 정렬에 편합니다. `.navigation`에서 로고, 메뉴, 버튼을 가로로 놓고 간격을 조절합니다. Grid는 행과 열을 함께 배치하기 편합니다.

```css
grid-template-columns: repeat(auto-fit, minmax(min(100%, 280px), 1fr));
```

- `auto-fit`: 공간에 들어가는 열을 자동 배치합니다.
- `minmax(..., 1fr)`: 최소 너비부터 남는 공간을 균등하게 채우는 너비까지 늘어납니다.
- `min(100%, 280px)`: 좁은 화면에서는 최소 너비도 부모보다 커지지 않게 합니다.

**실습:** 280px을 350px로 바꾸기 전에 열 수가 어떻게 달라질지 먼저 말해보세요.

## 4. DOM, 이벤트, 상태, 렌더링

| 개념 | 코드 예 | 역할 |
| --- | --- | --- |
| DOM | `querySelector("#theme-toggle")` | 화면 요소 찾기 |
| 이벤트 | `addEventListener("click", toggleTheme)` | 눌렀을 때 실행할 함수 연결 |
| 상태 | `state.theme` | 현재 선택 기억 |
| 렌더링 | `renderTheme()` | 기억한 값을 화면에 반영 |
| 영속 저장 | `localStorage.setItem(...)` | 새로고침 후에도 값 유지 |

`toggleTheme()` → `renderTheme()` → CSS의 `[data-theme="dark"]` 순서로 읽으세요. 새로고침 후에는 `readTheme()`가 저장값을 읽습니다.

**질문:** `renderTheme()` 호출을 지우면? 상태는 바뀌지만 화면에는 반영되지 않습니다. React에서는 상태 갱신 API가 렌더링을 예약하는 방식을 배우게 됩니다.

## 5. ES6+와 배열 메서드

```js
const { status, items, error } = state.projects;
items.map(createProjectCard).join("");
```

구조분해 할당은 객체에서 필요한 값을 꺼내 반복을 줄입니다. `map`은 각 객체를 카드 문자열로 바꾼 새 배열을 반환합니다. `join("")`은 쉼표 없이 하나의 문자열로 합칩니다. `forEach`는 새 배열 대신 각 요소에 이벤트를 달거나 관찰을 등록할 때 사용합니다.

템플릿 리터럴은 백틱과 `${값}`으로 문자열에 값을 넣습니다. HTML로 해석되는 외부 값은 `escapeHTML`을 거칩니다. HTML이 필요 없는 안내 문구는 `textContent`를 사용합니다.

화살표 함수는 짧은 콜백을 표현할 때 사용합니다. 일반 함수와 `this` 처리 등이 다르므로 모든 함수를 기계적으로 바꾸지는 않습니다.

**선택 실습:** `filter`로 언어가 JavaScript인 저장소만 선택한 뒤 `map`으로 렌더링해보세요. 필터는 현재 기본 구현에 포함하지 않았습니다.

## 6. 비동기 요청을 기다리는 동안

```text
loading → 렌더링 → fetch 대기 → HTTP 검사 → JSON 읽기 → 데이터 검사
→ success 또는 empty → finally에서 렌더링
오류 발생 시 → catch에서 error → finally에서 렌더링
```

`await`는 해당 비동기 함수가 결과를 기다리게 합니다. 브라우저 전체를 멈추지 않으므로 기다리는 동안 다른 버튼도 동작합니다.

`fetch`는 HTTP 오류에서도 응답을 반환하므로 `response.ok`를 검사합니다. `catch`는 실패를 상태에 기록하고, `finally`는 결과와 관계없이 타이머를 정리하고 화면을 갱신합니다. `AbortController`는 10초를 넘긴 요청을 취소합니다.

**질문:** 빈 배열과 인터넷 끊김은 같을까요? 전자는 성공했지만 데이터가 없는 경우, 후자는 데이터를 알 수 없는 경우입니다.

## 7. 폼의 검증과 표시

`validateField(field)`는 빈 문자열이면 통과, 오류 문자열이면 실패를 반환합니다. `renderForm()`은 오류를 표시하고 `aria-invalid`를 갱신합니다.

- `touched`: 사용자가 입력한 필드인지 기억합니다.
- `submitted`: 확인 버튼을 눌렀는지 기억합니다.
- `errors`: 필드별 오류 메시지입니다.
- `success`: 현재 검증 성공 여부입니다.

`novalidate`로 브라우저의 자동 오류 말풍선을 끄고 필드 근처에 직접 오류를 표시합니다. `required`와 `type="email"`은 입력의 의미를 남깁니다. `preventDefault()`는 기본 제출로 페이지가 이동하는 것을 막습니다.

이메일 정규식은 학습용 형식 검사이며 주소의 실제 존재를 확인하지 않습니다. 입력은 전송하거나 저장하지 않습니다.

## 8. 5분 설명 순서

| 시간 | 보여줄 것 | 설명할 핵심 |
| --- | --- | --- |
| 0~1분 | 화면과 HTML | 역할에 맞는 태그와 제목 |
| 1~2분 | 테마 버튼 | 클릭이 상태를 바꾸고 렌더 함수가 속성을 변경 |
| 2~3분 | 프로젝트 | 로딩·성공·빈 값·실패 |
| 3~4분 | 문의 폼 | 검증과 오류 표시 분리 |
| 4~5분 | 반응형 | Flexbox와 Grid 선택 이유 |

한 사람은 질문하고 다른 사람은 코드에서 근거를 찾습니다. 다음 회차에는 역할을 바꿉니다.
